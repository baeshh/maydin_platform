# 약국 운영 방식 — A형(기존 POS 병행) · B형(MAYDIN POS 전환)

약국마다 **재고 기준을 하나만** 둔다. 기존 POS를 계속 쓰면서 MAYDIN 온라인몰·픽업만 붙이는 약국은 **A형**, 매장 판매까지 MAYDIN POS로 옮긴 약국은 **B형**이다. 코드에서는 `stock_master`로 구분한다.

| | A형 · 기존 POS 병행 | B형 · MAYDIN POS 전환 |
| --- | --- | --- |
| `stock_master` | `LEGACY_POS` (병행 모드 켬) | `MAYDIN` |
| 재고 기준 | 기존 POS | MAYDIN |
| 입고·폐기·실사·재고 직접 수정 | **MAYDIN에서 막힘**(409) — 기존 POS에서 | MAYDIN에서 |
| 상품 일괄 등록 | 병행 동기화만 | 이전(덮어쓰기)·입고(더하기) |
| MAYDIN POS 판매 | 판매 즉시 MAYDIN 재고에서 차감 + 기존 POS에 입력할 목록에 올림 | 판매 즉시 차감 |
| 온라인 주문 | 재고 파일이 늦으면 자동 멈춤 | 항상 MAYDIN 재고로 |
| 장애 후 재고 대사 | 확인만 기록(수량은 기존 POS에서) | 실사 수량 입력 → 재고 맞춤 |

전환·설정 화면: 파트너센터 > 상품 일괄 등록 > 기존 POS와 병행. POS 상단에는 A형일 때 "재고 기준 기존 POS"(늦으면 "온라인 주문 멈춤")가 늘 보인다. 바꿀 때마다 감사 기록이 남는다. 재고 계산식·파일 형식은 [product-import-plan.md](product-import-plan.md)의 "재고 기준"을 본다.

## A형 — 기존 POS를 계속 쓰는 약국

### 재고가 어긋나지 않게 하는 방법

이 결정(기존 방식 유지)은 바꾸지 않는다: **MAYDIN에서 판 수량은 즉시 MAYDIN 재고에서 빼고**, 같은 수량을 기존 POS에 입력할 목록으로 내보낸다. 원장(ledger)을 따로 두지 않고 기존 "MAYDIN 판매 수량 내보내기" 방식을 그대로 쓴다.

1. 기존 POS 재고 파일을 주기(기본 24시간)마다 올린다 → **새 재고 = 파일 재고 − 파일 시각 이후 MAYDIN에서 판 수량.**
2. 온라인·픽업·MAYDIN POS 판매 수량을 내려받아 기존 POS에 입력하고 "입력했어요"를 누른다 → 다음 동기화부터 빼지 않는다.
3. 온라인에는 재고에서 여유분을 뺀 만큼만 보인다.
4. 재고 파일이 주기를 넘기면 온라인 주문을 멈춘다(`STOCK_SYNC_PAUSED`). 새 파일을 적용하면 바로 열린다. 상담 예약은 막지 않는다.

### 하루 운영

| 때 | 할 일 |
| --- | --- |
| 개점 | 기존 POS 재고 파일을 MAYDIN에 올린다(온라인 주문이 멈춰 있으면 이것으로 열린다) |
| 영업 중 | 매장 판매는 기존 POS. 픽업 수령·MAYDIN 회원 적립이 필요한 판매만 MAYDIN POS |
| 입고·폐기·실사 | 기존 POS에서만. MAYDIN에서 하려 하면 막힌다 |
| 마감 | MAYDIN 판매 수량을 내려받아 기존 POS에 입력 → "입력했어요". MAYDIN POS 카운터를 썼으면 MAYDIN 일마감도 한다 |

### 카드 결제

A형 약국의 카운터는 보통 기존 POS에 연결된 단말기를 그대로 쓴다. MAYDIN POS 카운터는 **수동 승인**(기존 단말기 단독 승인 → 승인번호 입력)으로 두고, 마감 때 단말기 영수증과 대조한다(대조하지 않으면 마감이 막힌다). 단말기를 MAYDIN 전용으로 둘 수 있으면 Bridge 연동을 쓸 수 있다.

## B형 — MAYDIN POS로 바꾼 약국

### 하루 운영

| 때 | 할 일 |
| --- | --- |
| 개점 | 카운터마다 영업 시작(시재 입력) |
| 영업 중 | 판매·환불·픽업·보류·상담 모두 MAYDIN POS. 입고·폐기·실사도 MAYDIN |
| 장애 | 인터넷·서버가 끊기면 장애 중 판매로 이 기기에 보관 → 복구 후 자동 전송 → 재고 대사([pos-outage-and-backup.md](pos-outage-and-backup.md)) |
| 마감 | 결과 미확정 승인 정리 → 수동 승인 대조 → 시재 확인 → 일마감 |

### 카운터·카드 결제 준비

1. 약국 관리자가 카운터 PC마다 POS에서 "이 PC를 카운터로 등록"한다. 한 대라도 등록하면 등록하지 않은 PC는 판매할 수 없다.
2. 카운터마다 카드 결제 방식을 고른다.
   - **수동 승인**: 계약·연동 전 기본값. 마감 때 대조 필수.
   - **MAYDIN Bridge 연동**: 카운터 PC에 Bridge를 설치하고 "Bridge 연결"([maydin-bridge-spec.md](maydin-bridge-spec.md)). 승인·취소가 서버에서 확인된다.
   - **VAN 자동 승인 (데모)**: 시연용. 실제 돈이 움직이지 않으며 "(데모)"가 붙는다.
   - **NICE·KIS 연동**: VAN 계약 후 가맹점 번호·TID·API 키를 서버 환경변수로 넣어야 고를 수 있다.

## 두 방식 사이 바꾸기

- **A형 → B형**: 마지막 기존 POS 재고 파일을 동기화한 뒤 재고 기준을 MAYDIN으로 바꾸고, 필요하면 "이전(덮어쓰기)"로 한 번 맞춘다. 이후 입고·실사는 MAYDIN에서 한다.
- **B형 → A형**: 재고 기준을 기존 POS로 바꾸면 첫 재고 파일을 적용할 때까지 온라인 주문이 멈춘다. 그 전 재고 파일은 세지 않는다.
