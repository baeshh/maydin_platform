# 다른 POS 상품·재고 일괄 등록 — 요구사항과 분석

다른 POS를 쓰던 창고형 약국이 상품과 재고를 파일 하나로 MAYDIN에 한 번에 넣을 수 있게 하는 기능의 요구사항과 분석입니다. 두 가지 쓰임을 모두 지원합니다.

- **B. 이전(마이그레이션):** 기존 POS를 그만 쓰고 MAYDIN POS로 옮길 때, 처음 한 번 상품·재고를 통째로 넣는다.
- **C. 병행 동기화:** 기존 POS를 계속 쓰면서, 기존 POS의 재고를 주기적으로 MAYDIN(온라인 몰)에 맞춘다.

두 쓰임은 "파일 올리기 → 열 맞추기 → 미리보기 → 한 번에 적용 → 이력·되돌리기"라는 같은 흐름을 쓰고, 재고를 계산하는 방식만 다릅니다.

## 0. 원칙

- 파일을 올리자마자 반영하지 않는다. 반드시 미리보기에서 신규·수정·오류를 확인한 뒤 적용한다.
- 적용은 전부 되거나 전부 안 된다. 중간에 실패하면 아무것도 바뀌지 않는다.
- 같은 상품인지는 바코드(또는 기존 POS 상품코드)로만 판단한다. 상품명이 비슷하다고 자동으로 합치지 않는다.
- 일반의약품이 온라인 몰에 잘못 노출되지 않는 쪽을 기본값으로 한다. 새로 들어온 상품은 약국이 확인하기 전까지 온라인에 보이지 않는다.
- 전문의약품은 가져오지 않는다. MAYDIN은 처방 조제를 다루지 않는다.
- 상품·재고 파일만 다룬다. 고객 명부·포인트·판매 이력은 이 기능의 범위가 아니다(11장 참고).
- 원본 파일은 서버에 보관하지 않는다. 적용 결과(행별 변경 전·후 값)만 이력으로 남긴다.

## 1. 쓰임별 흐름

### B. 이전

1. 영업을 마친 뒤 기존 POS에서 상품·재고 목록을 엑셀이나 CSV로 내려받는다.
2. 파트너센터 > 상품 관리 > "일괄 등록"에서 파일을 올리고 "이전" 모드를 고른다.
3. 열을 맞추고(처음 한 번), 미리보기에서 오류 행을 고치거나 제외한다.
4. 적용하면 재고는 파일 수량으로 덮어쓰고, 유통기한 열이 있으면 첫 로트도 만든다.
5. 새 상품은 POS에서 바로 팔 수 있고, 온라인 몰에는 약국이 "온라인 공개"를 눌러야 보인다.
6. 다음 날부터 MAYDIN POS로 판매한다. 이후 입고분은 "더하기" 모드로 다시 올릴 수 있다.

### C. 병행 동기화

1. 약국이 파트너센터 설정에서 "기존 POS와 병행" 모드를 켠다. 이때부터 입고·폐기·실사는 기존 POS에서만 한다(3.3 참고).
2. 매일(또는 정한 주기로) 기존 POS 재고 파일을 올린다. 열 맞추기는 저장해 둔 설정을 다시 쓴다.
3. 파일의 "재고 기준 시각"을 확인한다(기본값: 올린 시각).
4. MAYDIN은 기준 시각 이후 MAYDIN에서 나간 수량을 빼고 재고를 맞춘다(6.3의 계산식).
5. MAYDIN 온라인 판매 내역을 CSV로 내려받아 기존 POS에 출고로 입력하고, "여기까지 기존 POS에 입력함"을 표시한다.

## 2. 현재 시스템 분석

### 2.1 상품 데이터

| 필드 | 의미 | 비고 |
|---|---|---|
| `product_name` | 상품명 | 필수 |
| `barcode` | 바코드 | 약국 안에서 중복 불가(DB 고유 인덱스 `idx_products_pharmacy_barcode`) |
| `category_id` | 분류 | 상품 등록 시 분류 이름이 없으면 자동 생성 |
| `brand`, `supply_days` | 브랜드, 복용·사용 기간 | 선택 |
| `price` | 판매가(부가세 포함) | POS 영수증에서 과세 물품가액을 `price / 1.1`로 계산 |
| `discount_price` | 할인가 | 선택 |
| `cost_price` | 매입 원가 | 선택, 고객 화면에 노출 안 됨 |
| `stock_quantity` | 재고 | 0 이상 정수, 음수가 되면 DB 트리거가 거절 |
| `safety_stock` | 안전재고 | 발주 추천 기준 |
| `product_type` | `GENERAL` / `OTC`(일반의약품) | OTC는 온라인 몰·장바구니에서 제외 |
| `tax_type` | `TAXABLE` / `EXEMPT` | 과세·면세 |
| `status` | `ON_SALE` / `SOLD_OUT` / `HIDDEN` | `HIDDEN`은 온라인 몰과 POS 모두에서 숨김 |
| `pos_sale_enabled` | POS 판매 허용 | 0이면 POS 판매 중지 |
| `supplier_id` | 기본 거래처 | 선택 |

### 2.2 재고가 바뀌는 경로

| 경로 | 기록 유형 | 비고 |
|---|---|---|
| POS 판매·반품·취소 | `inventory_logs` (`ORDER` 참조) | |
| 온라인 주문(배송·픽업) | `ORDER` | 주문 시점에 재고 차감 |
| POS 입고 | `RECEIVE` | 유통기한 입력 시 로트 생성 |
| 발주 입고 | `RECEIVE` (`PURCHASE_ORDER` 참조) | 로트 생성 |
| 폐기 | `DISPOSE` | 로트 지정 가능, 관리자만 |
| 실사 조정 | `COUNT_ADJUST` | 관리자만, 차이가 있으면 사유 필수 |
| 상품 수정 화면 | `ADJUST` | |

### 2.3 재고 관련 DB 규칙

- **음수 재고 금지:** `trg_products_no_negative_stock`가 재고가 0 미만이 되는 변경을 거절한다.
- **로트 자동 차감:** `trg_products_consume_lots`는 재고가 줄었는데 로트 합계가 재고보다 크면, 유통기한이 늦은 로트를 남기고 빠른 로트부터 줄여 로트 합계를 재고에 맞춘다.
  - 일괄 덮어쓰기로 재고가 줄면 이 트리거가 로트를 알아서 맞춘다.
  - 재고가 늘면 로트 없이 늘어난다("유통기한 미상" 재고).

### 2.4 이번 기능에 없는 것(새로 필요한 것)

- 기존 POS 상품코드를 저장할 곳이 없다. 바코드 없는 상품(소분·자체 상품)은 다시 올릴 때 같은 상품을 찾을 수 없다.
- "POS에서는 팔되 온라인에는 숨김" 상태가 없다. 지금의 `HIDDEN`은 POS까지 막는다.
- 일괄 작업 단위(배치)와 되돌리기 기록이 없다.
- 열 맞추기 설정을 저장할 곳이 없다.
- 병행 동기화용 설정이 없다(기존 POS 반영 시각, 온라인 판매 여유분).

## 3. 기존 POS 파일의 현실(원천 데이터 분석)

실제 파일을 받기 전 일반적으로 예상되는 문제들입니다. 대상 약국의 실제 내보내기 파일로 반드시 다시 확인해야 합니다(10장).

### 3.1 형식

- 엑셀 `.xlsx`, 옛 엑셀 `.xls`, CSV가 섞여 온다.
- CSV는 대부분 한글 윈도우 인코딩(CP949/EUC-KR)이다. UTF-8과 자동으로 구분해야 한다.
- 첫 줄이 제목("재고현황 2026-10-10")이고 머리글이 2~3번째 줄에 있거나, 마지막에 합계 행이 붙는 경우가 많다.
- 시트가 여러 개일 수 있다.

### 3.2 열 이름

POS마다 다르므로 흔한 이름을 자동으로 짝짓고, 못 맞춘 열만 약국이 고른다.

| MAYDIN 항목 | 예상되는 열 이름 |
|---|---|
| 상품명 | 상품명, 품명, 제품명, 상품명칭 |
| 바코드 | 바코드, 바코드번호, 표준코드, EAN |
| 기존 POS 상품코드 | 상품코드, 품목코드, 코드, 자체코드 |
| 판매가 | 판매가, 소비자가, 판매단가, 정상가 |
| 할인가 | 할인가, 행사가 |
| 매입가 | 매입가, 입고가, 매입단가, 원가 |
| 재고 | 현재고, 재고, 재고수량, 현재재고 |
| 분류 | 분류, 대분류, 카테고리, 상품분류 |
| 구분 | 구분, 상품구분, 품목구분, 의약품구분 |
| 과세 | 과세구분, 과면세, 부가세구분 |
| 브랜드 | 브랜드, 제조사, 제약사 |
| 거래처 | 거래처, 매입처, 공급처 |
| 유통기한 / 로트 | 유통기한, 사용기한 / 제조번호, 로트 |
| 안전재고 | 안전재고, 적정재고, 최소재고 |

### 3.3 값의 문제

- **바코드**
  - 엑셀이 `8.80123E+12`처럼 지수로 바꿔 뒷자리가 사라진다. 복구할 수 없으므로 오류로 표시하고 "바코드 열을 텍스트로 저장" 안내를 띄운다.
  - 앞자리 0이 사라진다(예: `0123...`). 자릿수(8·12·13·14)와 체크 숫자로 검증한다.
  - 한 상품에 바코드가 여러 개(낱개·박스)인 경우가 있다. 1단계에서는 첫 번째만 쓰고 나머지는 경고로 보여 준다.
- **단위:** 박스 단위로 재고를 관리하던 약국이 있다. 1단계는 낱개 기준만 받고, 미리보기에 "재고 단위 확인" 안내를 띄운다.
- **가격**
  - 판매가 0원이나 빈칸이 있다. 판매가가 없으면 오류로 처리한다.
  - 매입가가 부가세 포함인지 별도인지 POS마다 다르다. 업로드할 때 고르게 한다.
- **재고:** 음수(기존 POS에서 마이너스 판매), 소수, 빈칸이 있다.
  - 음수는 0으로 넣고 경고한다.
  - 소수는 오류로 처리한다.
  - 빈칸은 "재고 변경 안 함"으로 처리한다.
- **구분:** 전문의약품·일반의약품·의약외품·건강기능식품·잡화가 섞여 있다. 구분 열이 아예 없는 경우도 많다(5장).
- **중복과 단종:** 같은 바코드가 두 줄에 나오면 둘 다 오류로 처리한다. 판매중지·단종 표시가 있는 상품은 POS 판매 중지로 넣거나 제외한다.

### 3.4 병행 동기화에서 생기는 근본 문제

실물 재고는 하나인데 판매 기록은 두 시스템에 나뉜다.

- 기존 POS 파일은 MAYDIN에서 팔린 수량(온라인 주문, 픽업)을 모른다.
- MAYDIN은 기존 POS에서 팔린 수량을 파일을 올리기 전까지 모른다.
- 그래서 파일 재고로 그냥 덮어쓰면 MAYDIN 판매분이 되살아나 재고가 실제보다 많아지고, 온라인에서 없는 물건이 팔린다(과판매).
- 입고를 두 시스템 모두에 넣으면 입고가 두 번 잡힌다.

해결 방법은 6.3에 정리했습니다.

## 4. 기능 요구사항

### 4.1 공통

- **IMP-01 업로드:** `.xlsx`, `.xls`, `.csv`를 받는다. 최대 20,000행, 파일 10MB.
- **IMP-02 인코딩:** CSV는 UTF-8과 CP949를 자동 판별하고, 틀렸을 때를 위해 수동 선택도 둔다.
- **IMP-03 시트·머리글:** 시트를 고르고, 머리글이 몇 번째 줄인지 자동으로 찾는다(수정 가능). 빈 행과 합계 행은 건너뛴다.
- **IMP-04 열 맞추기:** 3.2의 이름으로 자동 매칭하고 약국이 고칠 수 있다. 상품명·판매가는 필수이고, 바코드나 기존 POS 상품코드 중 하나가 있어야 다시 올릴 때 같은 상품을 찾는다.
- **IMP-05 설정 저장:** 열 맞추기와 옵션을 "프로필"로 저장한다(예: "기존 ○○POS 재고"). 다음 업로드 때 자동 적용한다.
- **IMP-06 미리보기:** 적용 전에 행마다 신규 / 수정 / 변화 없음 / 경고 / 오류로 나눈다. 수정 행은 바뀌는 값을 "재고 12 → 30", "판매가 15,000 → 14,000"처럼 보여 준다. 필터, 검색, 오류 행 CSV 내려받기를 지원한다.
- **IMP-07 행 제외:** 미리보기에서 특정 행을 빼고 적용할 수 있다. 오류 행은 자동으로 빠진다.
- **IMP-08 적용:** 하나의 트랜잭션으로 반영한다.
  - 재고가 바뀐 상품마다 재고 기록(`inventory_logs`, 유형 `IMPORT`)을 남긴다.
  - 감사 로그에 "일괄 등록 · 신규 N · 수정 N"을 남긴다.
- **IMP-09 업데이트할 항목 선택:** 기존 상품은 어떤 항목을 파일 값으로 바꿀지 고른다. 기본값은 재고·판매가·매입가이고, 상품명·분류·구분은 기본으로 바꾸지 않는다.
- **IMP-10 파일에 없는 상품:** MAYDIN에는 있는데 파일에 없는 상품은 기본값으로 그대로 둔다. 선택하면 품절(재고 0) 처리하거나 POS 판매 중지로 바꿀 수 있다.
- **IMP-11 이력:** 언제, 누가, 어떤 모드로, 몇 행을 적용했는지 목록으로 본다. 행별 변경 전·후 값을 볼 수 있다.
- **IMP-12 되돌리기:** 적용 후 24시간 안에 배치 단위로 되돌린다.
  - 상품 정보는 변경 전 값으로 되돌린다.
  - 재고는 일괄 등록으로 바뀐 만큼만 거꾸로 적용한다. 그 사이 판매가 있었으면 판매분은 그대로 반영된다.
  - 거꾸로 적용해서 음수가 되는 상품이 있으면 되돌리기 전체를 막고 목록을 보여 준다.
  - 새로 만든 상품은 판매·주문 이력이 없으면 지우고, 있으면 숨김 처리한다.
- **IMP-13 양식:** MAYDIN 표준 양식 CSV·엑셀을 내려받을 수 있다(기존 POS가 내보내기를 못 하는 약국용).
- **IMP-14 권한:** 약국 관리자(운영자)만 쓸 수 있다. POS 직원은 쓸 수 없다.
- **IMP-15 진행 중 판매:** 미리보기 이후 재고가 바뀐 상품은 적용할 때 다시 계산하고 결과 화면에 표시한다. 화면에는 "영업 마감 후 올려 주세요"를 안내한다.

### 4.2 B. 이전 전용

- **MIG-01 재고 방식:** "덮어쓰기"가 기본이다. 이후 입고분 업로드용으로 "더하기"를 고를 수 있다.
- **MIG-02 첫 로트:** 유통기한 열이 있으면 그 수량으로 첫 로트를 만든다. 지난 유통기한은 경고 후 로트 없이 넣는다.
- **MIG-03 분류·거래처:** 처음 보는 분류와 거래처는 만들 목록을 미리보기에서 보여 주고 함께 만든다.
- **MIG-04 이전 체크리스트:** 파트너센터에 순서를 안내한다. 기존 POS 마감 → 내보내기 → 업로드 → 실사 샘플 확인 → MAYDIN POS 시작.

### 4.3 C. 병행 동기화 전용

- **SYN-01 병행 모드:** 약국 설정에서 켜고 끈다. 켜져 있는 동안 지켜지는 것:
  - 파일 재고는 6.3 계산식으로 반영된다.
  - MAYDIN의 입고·폐기·실사 기능은 막고, "기존 POS에서 처리해 주세요"를 안내한다.
  - 상품 정보(이름·가격)를 기존 POS 기준으로 덮어쓸지는 프로필 옵션으로 정한다.
- **SYN-02 재고 기준 시각:** 업로드할 때 입력한다. 기본값은 올린 시각이고, 미래 시각은 쓸 수 없다.
- **SYN-03 온라인 판매 내역 내보내기:** 선택한 기간에 MAYDIN에서 나간 상품별 수량(온라인 배송·픽업, 반품 차감)을 CSV로 내려받는다. 기존 POS에 출고로 입력하기 위한 용도다.
- **SYN-04 반영 표시:** 내보낸 뒤 "여기까지 기존 POS에 입력함"을 누르면 그 시각을 저장한다(6.3의 E).
- **SYN-05 온라인 여유분:** 다음 동기화 전까지 과판매를 막기 위해 온라인 몰 판매 가능 수량을 "재고 − 여유분"으로 보여 준다. 기본값 1개, 약국 설정에서 바꾼다.
- **SYN-06 차이 리포트:** 동기화마다 "MAYDIN 재고와 파일 재고 차이가 큰 상품"을 보여 준다. 기준은 차이 10개 이상 또는 30% 이상이다.
- **SYN-07 미동기 경고:** 마지막 동기화가 정한 주기(기본 24시간)보다 오래되면 파트너센터에 경고를 띄운다.

### 4.4 행 검증 규칙

| 항목 | 규칙 | 실패 시 |
|---|---|---|
| 상품명 | 1~100자 | 오류 |
| 바코드 | 숫자 8·12·13·14자리, 체크 숫자 일치. 지수 표기 감지 | 지수 표기·자릿수 이상은 오류, 체크 숫자 불일치는 경고 |
| 기존 POS 상품코드 | 1~40자 | 오류 |
| 바코드·상품코드 둘 다 없음 | 신규로만 들어감. 다시 올리면 또 신규가 됨 | 경고 |
| 판매가 | 0보다 큰 정수(쉼표·"원" 제거) | 오류 |
| 할인가 | 판매가보다 작음 | 경고 후 비움 |
| 매입가 | 0 이상 정수. 부가세 포함이면 별도로 환산 | 오류 |
| 재고 | 정수. 음수는 0으로, 빈칸은 변경 안 함 | 소수는 오류, 음수는 경고 |
| 구분 | 5장 규칙으로 변환 | 알 수 없음은 "확인 필요" |
| 과세 | 과세/면세/영세 → TAXABLE/EXEMPT | 알 수 없으면 과세 + 경고 |
| 유통기한 | 날짜 형식 여러 종류 인식(2026-10-10, 20261010, 26.10.10) | 형식 오류는 경고 후 로트 생략 |
| 같은 파일 안 중복 | 바코드 또는 상품코드가 같은 행 | 해당 행 모두 오류 |

### 4.5 비기능

- 20,000행 미리보기 5초 안, 적용 10초 안.
- 적용 중 실패하면 전부 취소된다.
- 파일 안에 개인정보(고객 이름·전화번호) 열이 보이면 그 열은 읽지 않고 경고한다.
- 모든 적용과 되돌리기는 감사 로그에 남긴다.

## 5. 일반의약품·전문의약품 분류

일반의약품이 일반 상품으로 잘못 들어가면 온라인 몰에 노출되어 "일반의약품은 대면 판매만" 원칙을 어기게 됩니다. 이 기능에서 가장 위험한 부분입니다.

- **구분 열이 있을 때**

  | 파일 값 | 처리 |
  |---|---|
  | 일반의약품, 일반약, OTC | `OTC` |
  | 의약외품, 건강기능식품, 건기식, 화장품, 잡화, 기타 | `GENERAL` |
  | 전문의약품, 전문약, ETC | 가져오지 않음(제외 + 안내) |
  | 그 밖의 값 | "확인 필요" |

- **구분 열이 없거나 "확인 필요"일 때:** `GENERAL`로 넣되 온라인에는 숨기고 "구분 확인 필요" 표시를 단다.
- **온라인 공개:** 새로 들어온 상품은 구분과 관계없이 온라인 비공개로 시작한다. 파트너센터에서 "확인 필요" 목록을 보고 구분을 정한 뒤 공개한다. 여러 개를 한 번에 공개할 수 있다.
- **기존 상품:** 일괄 등록이 기존 상품의 구분을 바꿀 때는 미리보기에서 강조한다. `GENERAL`에서 `OTC`로 바뀌면 지금처럼 장바구니에서도 뺀다.
- **2단계(자동 판별):** 건강보험심사평가원·식약처의 의약품 표준코드 공공데이터와 바코드를 대조한다.
  - 의약품으로 등록된 바코드는 자동으로 "의약품 의심" 표시를 단다.
  - 전문/일반 구분이 확인되면 자동으로 채운다.

## 6. 핵심 설계 결정

### 6.1 같은 상품 찾기

1. 바코드가 같은 상품
2. (없으면) 기존 POS 상품코드가 같은 상품
3. (둘 다 없으면) 신규

- 상품명으로는 자동 매칭하지 않는다.
- 미리보기에서 "이름이 같은 기존 상품이 있음" 경고를 띄우고, 약국이 직접 연결할 수 있게 한다(연결하면 그 상품에 기존 POS 상품코드가 저장된다).
- 파일 행의 바코드로는 A 상품, 상품코드로는 B 상품이 찾아지면 충돌로 보고 오류 처리한다.

### 6.2 재고 반영 방식

| 모드 | 계산 | 쓰임 |
|---|---|---|
| 덮어쓰기 | 새 재고 = 파일 재고 | B 첫 이전, 재고 실사 결과 반영 |
| 더하기 | 새 재고 = 현재 재고 + 파일 수량 | 입고 파일 |
| 동기화 | 6.3 계산식 | C |

### 6.3 병행 동기화 계산식

기호는 다음과 같습니다.

- T: 파일의 재고 기준 시각
- E: "여기까지 기존 POS에 입력함"으로 표시한 시각(처음 병행 모드를 켠 시각부터 시작)
- MAYDIN 순출고(E 이후): E 이후 MAYDIN에서 나간 수량 − 돌아온 수량(취소·반품)

```
새 재고 = 파일 재고(T 기준) − MAYDIN 순출고(E 이후)
```

- 기존 POS 파일에는 E까지의 MAYDIN 판매만 반영되어 있다. 그래서 E 이후에 MAYDIN에서 나간 것만 빼면 실물과 맞는다.
- 약국이 MAYDIN 판매분을 기존 POS에 한 번도 입력하지 않아도 계산은 맞는다. E가 처음 시각에 머물러 있어서, 그동안의 MAYDIN 판매 전체를 빼기 때문이다. 다만 기존 POS 자체의 재고는 계속 틀린 채로 남으므로, SYN-03 내보내기로 입력하는 것을 권장한다.
- T 이후 업로드 직전까지 기존 POS에서 팔린 수량은 알 방법이 없다. 그래서 내보낸 직후에 올리도록 안내하고, 온라인 여유분(SYN-05)으로 과판매 위험을 줄인다.
- 결과가 음수면 0으로 넣고 차이 리포트에 표시한다.

예시

- 파일 재고 20, E 이후 MAYDIN 온라인 판매 3개, 그중 1개 반품 → 새 재고 = 20 − (3 − 1) = 18.
- 약국이 E를 업로드 직전으로 옮겼다면(그 3개를 기존 POS에 입력하고 표시함) → 새 재고 = 20.

입고·폐기·실사를 병행 모드에서 막는 이유:

- MAYDIN에서 입고하고 기존 POS에서도 입고하면 두 번 더해진다.
- MAYDIN에서만 입고하면, 다음 파일에 그 입고가 없어서 덮어쓸 때 사라진다.
- 따라서 재고를 늘리고 줄이는 작업은 기존 POS 한 곳에서만 한다.

### 6.4 온라인 공개 여부를 분리

- `products.online_visible`(기본 1)을 새로 둔다. 온라인 몰 조회는 `online_visible = 1`인 상품만 보여 준다.
- 기존 `HIDDEN`은 지금처럼 "판매 중지(POS·온라인 모두)" 의미로 유지한다.
- 일괄 등록으로 새로 만든 상품은 `online_visible = 0`으로 시작한다.

### 6.5 로트·유통기한

- 덮어쓰기로 재고가 줄면 기존 트리거가 유통기한 빠른 로트부터 줄인다. 따로 처리할 것이 없다.
- 재고가 늘었는데 유통기한 열이 없으면 늘어난 만큼은 로트 없는 재고가 된다. 상품 상세에 "유통기한 미상 N개"로 보인다.
- 유통기한 열이 있으면 이렇게 처리한다.
  - B 이전: 파일 수량 전체를 로트 하나로 만든다(기존 로트가 없을 때만).
  - 더하기: 더한 수량으로 로트를 만든다.

### 6.6 파일 읽는 위치

| 방식 | 장점 | 단점 |
|---|---|---|
| 브라우저에서 읽고 행만 서버로 보냄 (추천) | 파일이 서버에 저장되지 않음, 업로드 처리 불필요, 서버 부담 적음 | 브라우저용 엑셀 라이브러리 필요 |
| 서버에서 읽음 | 브라우저 차이 없음 | 파일 업로드·임시 저장·삭제 처리 필요, 서버 메모리 부담 |

- 엑셀 라이브러리는 SheetJS 공식 배포본(cdn.sheetjs.com)을 고정 버전으로 내려받아 `public`에 둔다. npm에 올라간 옛 버전은 알려진 보안 취약점이 있어 쓰지 않는다.
- 서버는 받은 행을 처음부터 다시 검증한다. 브라우저 검증은 편의용이다.

### 6.7 동시성

- 미리보기 결과는 서버에 배치로 저장한다. 적용 때 각 상품의 현재 재고를 다시 읽어 계산한다.
- better-sqlite3는 트랜잭션 동안 다른 쓰기를 기다리게 한다. 20,000행 적용은 1초 안팎이라 POS 판매가 잠깐 기다리는 정도다.

## 10. 테스트 계획

- **파일 읽기:** CP949 CSV, UTF-8 BOM CSV, 머리글이 3번째 줄인 엑셀, 합계 행, 빈 행
- **바코드:** 지수 표기 오류, 앞자리 0, 체크 숫자 경고, 파일 내 중복 오류, 바코드·상품코드 충돌
- **매칭:** 바코드 우선 → 상품코드 → 신규, 이름만 같은 상품은 신규 + 경고
- **재고**
  - 덮어쓰기·더하기 결과
  - 음수 → 0 + 경고
  - 소수 → 오류
  - 빈칸 → 변경 없음
  - 줄어든 재고에서 로트가 유통기한 빠른 순으로 줄어드는지
- **구분**
  - 일반의약품 → `OTC`이고 온라인 몰·장바구니에서 제외되는지
  - 전문의약품 행이 제외되는지
  - 알 수 없는 구분 → 확인 필요 + 온라인 비공개
- **적용·되돌리기**
  - 오류 행이 있어도 나머지는 적용되는지
  - 적용 중 오류 시 전부 취소되는지
  - 되돌리기 후 판매분만 남는지
  - 음수가 될 때 되돌리기가 막히는지
- **권한:** POS 직원 403, 다른 약국 배치 접근 404
- **병행 동기화**
  - 6.3 예시 그대로(20 − (3 − 1) = 18)
  - E를 옮긴 뒤 20
  - 미래 기준 시각 거절
  - 병행 모드에서 POS 입고 차단
  - 온라인 여유분 반영
- **성능:** 20,000행 미리보기·적용 시간

## 11. 범위 밖(별도 검토)

- **고객 명부 이전:** 기존 POS의 고객 이름·전화번호를 MAYDIN 회원으로 바로 만들 수 없다. MAYDIN 회원은 영수증 구매 인증과 약관·개인정보·민감정보 동의를 거쳐야 하기 때문이다. 필요하면 "기존 고객 초대 문자" 같은 별도 기능으로 다룬다.
- **포인트 잔액 이전:** 기존 POS 포인트를 옮기려면 회원 연결이 먼저 필요하다. 약국이 회원별로 수동 조정하는 것을 기본으로 한다.
- **판매 이력 이전:** 재구매 예정일·함께 산 상품 분석에 도움이 되지만, 회원 연결 없이 상품 단위 집계로만 쓸 수 있다. 수요 분석용으로 별도 검토한다.

## 12. 대표가 정할 것

- **실제 기존 POS 이름과 내보내기 파일 샘플:** 가장 중요하다. 대상 약국 1~2곳의 실제 파일로 3장의 가정을 확인하고 자동 매칭 이름을 보강한다.
- **C 모드에서 상품명·가격의 기준:** 기존 POS 기준으로 계속 덮어쓸지, 재고만 맞출지. 기본값은 재고만이다.
- **파일에 없는 상품 처리:** 기본값은 그대로 두는 것이다.
- **온라인 여유분 기본값:** 1개로 시작한다.
- **동기화 주기와 경고 기준:** 기본값은 24시간이다.
- **되돌리기 가능 기간:** 기본값은 24시간이다.
- **전문의약품 행 제외:** 제외하는 것이 기본값이다.
- **박스 단위 재고를 쓰는 약국이 있는지:** 있으면 3단계의 환산 기능을 앞당긴다.
