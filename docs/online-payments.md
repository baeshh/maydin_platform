# 온라인 결제 (배송·매장 픽업)

## 원칙

- **주문은 결제사 승인을 서버가 확인한 뒤에만 만든다.** 결제 전·결제 실패한 건은 `orders`에 없으므로 매출·재고·리포트에 잡히지 않는다.
- 카드번호·유효기간 등 결제수단 정보는 받지도 저장하지도 않는다. 결제사가 준 결제 키·영수증 주소·승인 시각만 둔다.
- 일반의약품은 지금처럼 온라인 결제 대상이 아니다(일반 상품만).
- 운영 서버는 **실결제가 확실히 켜진 경우에만** 온라인 결제를 연다. 설정이 빠졌거나 데모·테스트 키면 결제 요청이 503으로 막힌다.

## 흐름

1. **결제 요청** `POST /api/payments/checkouts`
   - 장바구니·금액·배송지를 서버가 고정한다(`online_checkouts`, 주문서는 암호화).
   - 주문번호(`pg_order_id`)도 이때 정한다. 주문·재고는 아직 건드리지 않는다.
   - 같은 장바구니로 결제 중인 요청이 있으면 새로 만들지 않고 이어 쓴다.
   - 10분 안에 같은 상품을 이미 결제했으면 고객 확인을 받는다(`DUPLICATE_SUSPECTED`).
2. **결제창**: 토스페이먼츠 결제창(또는 `(데모)` 결제창)에서 고객이 인증한다.
3. **승인** `POST /api/payments/confirm`
   - 결제창에서 넘어온 금액이 서버 금액과 다르면 결제사에 승인을 요청하지 않는다. 승인 요청을 안 하면 청구되지 않는다.
   - 결제 시간이 지났거나 재고가 없어도 승인하지 않는다.
   - 결제 요청을 `CONFIRMING`으로 잠근 뒤 결제사에 승인을 요청한다(멱등 키 `confirm-{주문번호}`). 같은 요청이 동시에 와도 승인은 한 번이다.
   - 응답의 상태(`DONE`)·주문번호·금액·결제 키를 다시 맞춰 본 뒤, 한 트랜잭션에서 주문 생성 + 재고 차감 + 결제 기록 + 이력(생성 → 결제 대기 → 결제 완료)을 남긴다.
   - 승인 뒤 재고가 없거나 검증이 맞지 않으면 그 자리에서 결제를 취소한다(`CANCELED`). 취소가 실패하면 `REFUND_REQUIRED`로 두고 정산 작업이 다시 시도한다.
4. **결과를 모를 때**(시간 초과·5xx)
   - `UNKNOWN`으로 두고 결제사에 조회해 맞춘다.
   - 인증만 되고 승인 전이면 같은 멱등 키로 승인을 다시 요청한다.
   - 결제창 결과 화면(`pay-result.html`)이 2초 간격으로 확인한다.

## 정산 작업 (기본 60초마다, `PAYMENT_RECONCILE_INTERVAL_SECONDS`)

- 결제 시간(기본 30분, `PAYMENT_CHECKOUT_TTL_MINUTES`)이 지난 결제 요청은 만료 처리하고 주문서를 파기한다.
- `UNKNOWN`·`REFUND_REQUIRED`, 그리고 2분 넘게 멈춘 `CONFIRMING` 건은 결제사에 조회해 마무리한다.
- 결제사 취소 도중 멈춘 주문(취소 잠금)을 이어서 처리한다.
- 관리자가 바로 돌리려면 `POST /api/payments/reconcile`을 호출한다.

## 웹훅 `POST /api/payments/webhook/toss`

- 본문의 상태·금액은 믿지 않는다. 결제 키·주문번호만 꺼내 결제사 API로 다시 조회한 결과로 처리한다.
- 같은 이벤트(`tosspayments-webhook-transmission-id`, 없으면 본문 해시)는 한 번만 처리한다(`payment_events`).
- 처리에 실패하면 500으로 답해 결제사가 다시 보내게 한다.
- 결제사 쪽에서 취소된 경우:
  - 전액 취소이고 아직 취소·환불할 수 있는 주문이면 주문도 자동으로 취소·환불한다.
  - 부분 취소이거나 배송 중이면 자동으로 바꾸지 않는다. 파트너센터 주문 목록에 알림(`payment_alert`)을 띄우고, 약국이 확인 메모를 남겨 해제한다.

## 취소·환불

1. 주문을 잠근다(`cancel_lock_at`). 잠긴 동안에는 상태 변경·카운터 수령이 막힌다.
2. 결제사에 취소를 요청한다(멱등 키 `cancel-{결제ID}-{결제키}`).
3. 결제사가 전액 취소를 확인해 준 뒤에만 다음을 한 번에 처리한다: 결제 취소 기록, 재고 원복, 음수 매출, 이력.
4. 결제사 응답에 따라 이렇게 처리한다:
   - 결제사가 거절하면 주문은 그대로 두고 잠금을 풀며 502(`PG_CANCEL_FAILED`)로 알린다.
   - 응답이 끊기면 잠금을 유지한다(502 `PG_CANCEL_PENDING`). 정산 작업이나 웹훅이 결제사 상태를 확인해 마무리한다.
5. 환불은 지금처럼 전액만 지원한다.

## 설정

| 변수 | 설명 |
| --- | --- |
| `PG_PROVIDER` | `DEMO`(기본) · `TOSS` · `NONE` |
| `TOSS_CLIENT_KEY` / `TOSS_SECRET_KEY` | 토스페이먼츠 키. `test_`는 테스트, `live_`는 실결제. 두 키 종류가 다르면 결제가 닫힌다 |
| `PG_LIVE_ENABLED=true` | 실결제 키로 운영을 시작할 때만 켠다. 없으면 실결제 키가 있어도 결제를 막는다 |
| `MAYDIN_STAGING=true` | 스테이징 서버(운영과 다른 DB)에서만 테스트 키·데모 결제 허용. 운영 DB에는 켤 수 없다([payment-test-policy.md](payment-test-policy.md)). 예전 `ALLOW_TEST_PAYMENTS`·`ALLOW_DEMO_PAYMENTS`는 더 이상 쓰지 않는다 |
| `TOSS_API_BASE` | 결제사 API 주소(테스트용 가짜 서버 지정) |
| `PG_TIMEOUT_MS` | 결제사 응답 대기(기본 15000) |
| `PAYMENT_CHECKOUT_TTL_MINUTES` · `PAYMENT_STALE_SECONDS` · `PAYMENT_RECONCILE_INTERVAL_SECONDS` | 결제 시간 · 멈춤 판정 · 정산 주기 |

데모·테스트 결제로 접수된 주문은 파트너센터에 빨간 글씨로 `(데모) 결제 · 실제 입금 없음`, `토스페이먼츠 (테스트) · 실제 입금 없음`으로 표시된다.

## 실결제 전환 전 확인 (모두 끝나기 전에는 `PG_LIVE_ENABLED`를 켜지 않는다)

- [ ] 토스페이먼츠 가맹 계약·심사 완료, 판매 상품 범위(일반 상품만) 확인
- [ ] **테스트 키**로 스테이징에서 실제 결제창 왕복 확인
  - 승인, 카드 거절, 결제창 닫기, 새로고침·뒤로가기 후 재승인 시도
  - 같은 주문을 두 창에서 결제
- [ ] 토스 개발자센터에 웹훅 URL 등록: `https://<도메인>/api/payments/webhook/toss` (HTTPS 필수)
- [ ] 결제사 관리 화면에서 직접 취소 → 웹훅으로 주문 자동 취소 확인
- [ ] 고객 취소 · 약국 취소 · 수령 후 환불이 결제사 취소 내역과 금액이 맞는지 확인
- [ ] 결제사 응답 지연(타임아웃) 상황에서 정산 작업이 승인·취소를 마무리하는지 확인
- [ ] 운영 서버 `NODE_ENV=production`, `MAYDIN_STAGING` 미설정, `npm run security:check`에 데모·테스트 결제 없음 확인
- [ ] 시크릿 키는 서버 환경변수로만 두고 저장소·클라이언트에 노출하지 않기
- [ ] 정산(입금) 대사: 결제사 정산 내역과 주문·환불 금액 일치 확인 절차 마련
- [ ] 위가 끝나면 실결제 키 + `PG_LIVE_ENABLED=true`
