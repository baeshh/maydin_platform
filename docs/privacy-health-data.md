# 회원 개인정보 · 건강 정보 처리 방침 (구현 기준)

메이딘은 **가입에 꼭 필요한 정보만 받고**, 알레르기·복용 약 같은 건강 정보는 **복약상담에 쓰려는 회원에게만, 가입과 따로 동의를 받아** 보관한다. 건강 정보와 상담 문의 내용은 약사만 목적을 남기고 열람하며, 고객은 누가 언제 왜 봤는지 앱에서 확인한다. 보유기간이 지나거나 동의를 철회·탈퇴하면 지운다.

> 이 문서는 현재 코드가 실제로 하는 일을 적은 것이다. 개인정보 처리방침·약관 문구는 법률 검토를 거쳐 확정한다.

## 1. 무엇을 언제 받나

| 단계 | 항목 | 필수 여부 | 이유 |
| --- | --- | --- | --- |
| 회원가입 | 이름, 휴대폰 번호 | 필수 | 회원 확인, 로그인 아이디 |
| 회원가입 | 생년월일 | 필수 | 만 14세 미만 가입 차단, PIN에 생년월일 사용 금지 확인 |
| 회원가입 | 로그인 PIN 6자리 | 필수 | 로그인 (bcrypt 해시로만 저장) |
| 회원가입 | 영수증 가입 코드 | 필수 | 실제 매장 구매 고객인지 확인(폐쇄몰) |
| 회원가입 | 이용약관 · 개인정보 수집·이용 동의 | 필수 | |
| 회원가입 | 성별, 주소, 추천인 코드, 마케팅 수신 | 선택 | 주소는 배송 주문 때 입력해도 된다 |
| 가입 후 · 복약상담 | 알레르기, 복용 중인 약 | 선택 · **별도 민감정보 동의** | 함께 먹으면 안 되는 약 확인 |
| 상담 예약 | 미리 전할 내용(증상·복용 약) | 선택 · **예약마다 동의** | 상담 준비 |

- **가입 화면에는 건강 정보 입력란과 민감정보 동의가 없다.** 가입 요청에 건강 정보나 `HEALTH_INFO` 동의를 보내도 서버가 무시한다(`routes/auth.js` `parseSignup`).
- 건강 정보 동의를 하지 않아도 멤버십·포인트·주문·상담 예약을 똑같이 쓸 수 있다.
- 건강 정보 동의는 고객 본인만 할 수 있다(앱 > 내 정보 > 알레르기·복용 약). 약국은 동의를 대신 받을 수 없고, 고객이 동의한 경우에만 상담 중 들은 내용으로 고칠 수 있다.
- 상담 예약의 "미리 전할 내용"을 적으면 그 예약에 대한 민감정보 동의 체크가 필요하다. 비우면 동의 없이 예약된다. 내용은 `orders.counsel_note`에 AES-256-GCM 암호문으로만 저장하고, 일반 메모 칸(`orders.memo`)에는 남기지 않는다. 이전에 평문 메모로 들어온 상담 예약은 서버 시작 시 암호문으로 옮겼다.
- 주민등록번호·카드번호·비밀번호 원문은 받지 않는다(기존 원칙 그대로).

## 2. 누가 볼 수 있나

| 정보 | 고객 본인 | 약사(약국 대표 계정) | POS 직원 | 플랫폼 관리자 |
| --- | --- | --- | --- | --- |
| 알레르기·복용 약 | 보기·수정·삭제 | **목적 선택 후** 열람, 동의한 고객만 수정 | 불가(있음 표시도 안 보임) | 불가 |
| 상담 미리 전한 내용 | 보기·삭제 | 열람(목적: 복약상담) | 불가("있음"만 표시) | 불가 |
| 열람·수정·삭제 기록 | 본인 기록 보기 | 고객별 기록 보기 | 불가 | 감사 로그 |

- 열람 목적은 세 가지 중 하나를 골라야 한다: **복약상담 / 판매 전 함께 먹으면 안 되는 약 확인 / 고객 요청에 따른 확인·정정**. 목적 없이 요청하면 400.
- 열람·수정·삭제는 `admin_logs`에 `HEALTH_VIEW`, `HEALTH_UPDATE`, `COUNSEL_NOTE_VIEW`, `HEALTH_EXPIRED`, `HEALTH_CONSENT_WITHDRAWN`으로 남고 `purpose` 칸에 목적을 적는다.
- 고객 앱의 "내 건강 정보 이용 기록"은 일시·내용·누가(약사/본인/시스템)·목적만 보여 준다.
- 주문 목록·POS 상담 목록·대시보드 응답에는 상담 내용 암호문도 내보내지 않고 `has_counsel_note`/`has_note`만 준다.

## 3. 동의 철회

| 무엇을 | 어디서 | 결과 |
| --- | --- | --- |
| 건강 정보 동의 | 앱 내 정보 "동의 철회 · 삭제", 또는 약국이 고객 요청으로 대리 철회 | 철회 기록 + 건강 정보 즉시 삭제 + 이용 기록에 "동의 철회로 삭제" |
| 상담 미리 전한 내용 | 앱 주문·예약 내역 "문의 내용 삭제" | 암호문 삭제, 삭제 시각 기록. 예약은 유지 |
| 마케팅 수신 | 앱 · 약국 대리 | 기존과 같음 |
| 필수 동의(약관·개인정보) | 회원 탈퇴로만 | 아래 5절 |

## 4. 보유기간과 자동 파기

| 대상 | 기간(기본값) | 기준 | 설정 |
| --- | --- | --- | --- |
| 알레르기·복용 약 | 24개월 | 마지막 저장·확인 시각 | `HEALTH_RETENTION_MONTHS` |
| 상담 미리 전한 내용 | 365일 | 예약의 마지막 변경 시각 | `COUNSEL_NOTE_RETENTION_DAYS` |
| 거절된 가입 신청 | 30일 | 거절 시각 | `REJECTED_SIGNUP_RETENTION_DAYS` |
| 탈퇴·파기 회원 주문의 연락처·배송지 | 5년 | 주문 시각 | `TRANSACTION_RETENTION_YEARS` |

- 고객 앱은 건강 정보 아래에 "OO까지 보관, 그때까지 확인이 없으면 자동 삭제"를 보여 주고, **"내용 그대로예요"** 버튼으로 기간을 다시 시작할 수 있다. 약사가 상담 중 고쳐도 다시 시작된다.
- 파기 작업(`services/privacy.js` `runRetention`)은 **서버가 켜질 때 한 번, 그 뒤 하루 한 번** 돈다(`RETENTION_INTERVAL_HOURS`, 테스트 환경에서는 꺼짐). 수동 실행: `npm run retention`, 또는 관리자 API `POST /api/admin/privacy/retention`.
- 실행할 때마다 처리 건수를 `PRIVACY_RETENTION` 로그로 남긴다.

## 5. 회원 탈퇴(삭제 절차)

- **고객 본인**: 앱 내 정보 > 회원 탈퇴. 안내 확인 체크 + PIN 재입력(틀리면 PIN 잠금 규칙 적용).
- **약국 대리**: 파트너센터 회원 상세 > 회원 탈퇴 처리. 본인 확인 체크 + 요청 경로(방문·전화) 필수. POS 직원·플랫폼 관리자는 할 수 없다.
- 진행 중인 배송·픽업 주문(결제 전·결제 완료·준비·배송·픽업 대기)이 있으면 409로 막는다. 받거나 취소한 뒤 탈퇴한다.

한 트랜잭션에서 다음을 처리한다.

1. 남은 상담 예약을 취소하고 이력에 "회원 탈퇴"를 남긴다.
2. 동의 중인 모든 항목에 철회 기록을 남긴다.
3. 회원·로그인 계정의 이름을 "탈퇴회원"으로, 휴대폰·생년월일·성별·PIN·가입 IP 해시·건강 정보를 지우고, 이메일은 `erased-<id>@erased.local`, 비밀번호는 아무도 모르는 값으로 바꾼다. 계정 상태는 `WITHDRAWN`이라 기존 토큰도 바로 막힌다.
4. 배송지, 장바구니, 가족 연결, 입고 알림을 지우고 상품 요청의 회원 연결을 끊는다. 쓰지 않은 인증 코드는 무효로 한다.
5. 상담 미리 전한 내용을 모두 지운다.
6. 남은 포인트는 소멸 처리(`ADJUST` 기록)한다.
7. `CUSTOMER_WITHDRAW` 감사 로그를 남긴다(회원코드만, 이름·번호 없음).

- **남기는 것**: 주문·결제·환불·포인트 내역(금액·품목). 전자상거래법상 거래 기록 보존 의무 때문이며, 이름·연락처 없이 남는다. 주문에 적힌 연락처·배송지는 보존기간(5년)이 지나면 4절 작업이 지운다.
- 탈퇴한 회원코드는 POS에서 회원으로 잡히지 않고, 회원 목록·분석·가족 연결 검색에서 빠진다. 같은 번호로 다시 가입할 수 있다(새 회원).

## 6. 백업과 삭제

- 백업 파일(`server/backups/`, 기본 6시간마다 · 최근 30개)에는 탈퇴 전 정보가 남는다. **삭제한 정보는 최대 약 8일(6시간 × 30개) 동안 백업에 남았다가 백업이 교체되며 사라진다.** 처리방침에 이 기간을 적고, `BACKUP_KEEP`·`BACKUP_INTERVAL_HOURS`를 바꾸면 함께 고친다.
- 백업으로 복원하면 지운 정보가 DB에 되살아난다. 이를 막기 위해 탈퇴·거절 파기 때 **회원 번호만** DB 밖의 파기 장부(`data/privacy-erasures.jsonl`, `PRIVACY_ERASURE_LEDGER`로 변경 가능)에 적는다. 복원은 서버를 멈춘 뒤에만 할 수 있고, 서버가 다시 켜지면 파기 작업이 장부를 읽어 되살아난 회원 정보를 다시 지운다.
- 파기 장부는 백업과 함께 지우지 않는다. 서버를 옮길 때 `data/` 폴더와 함께 옮긴다.

## 7. 확인 방법

- 자동 테스트: `node tests/run.mjs phase11` (가입 최소화, 상담 내용 암호화·권한, 열람 목적, 이용 기록, 동의 철회, 보유기간 파기, 탈퇴, 복원 후 재파기, 예전 메모 이전 — 80개 항목).
- 운영 점검: 관리자 `GET /api/admin/privacy/retention`으로 최근 파기 실행 기록과 설정값을 확인한다.
